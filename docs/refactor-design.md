# 红纸鸢重构设计

**日期**：2026-09-13（2026-09-14 增补：作者权主轴、回看账、节点剥夺、界面分层侵蚀）
**状态**：已实施。第一章垂直切片完成，回归 18 节 / 变异体 39 个全绿
**目标**：把当前文字推理项目重构为以规则恐惧和主体性恢复为核心的完整中文恐怖游戏。

## 1. 核心命题

> 玩家为了带走失踪的未婚妻而寻找规则，最终发现规则一直在替他完成婚礼。

**第二层命题（2026-09-14 定）：** 这作真正被夺走的是**玩家对自己语言的作者权**。代价体系收走的是"字"，不是生命值——游戏逐步开始替他说话，最后替他写下他自己的名字。

**为什么必须有真实后果（诊断）：** 恐惧 = 玩家在乎的东西 × 真的可能失去它 × 不知道何时以什么方式失去。三个因子相乘，任一为零则整体为零。纯文字游戏若违规只赚文本不付账，"乱点"就成了最优解，恐惧随之崩塌。互动媒介还多一个放大器：**后果是你自己造成的**。所以规则必须真的咬人——但咬的是措辞与痕迹，不是数值。

玩家开局只有一个具体目标：在婚期结束前找回失踪的新娘，否则村路封锁。

随着调查推进，目标被拆成三层：

- 表层：找到新娘身体或遗物。
- 中层：判断哪些规则在束缚她。
- 深层：确认她是否还拥有“愿意”和“拒绝”的能力。

真正的胜利不是把新娘带出村子，而是让她能够决定自己是否离开。

## 2. 恐怖结构

### 2.1 主轴：规则恐惧

所有规则都伪装成保护措施。玩家会不断得到正确但有害的信息：遵守规则能活到下一章，却使新娘更接近仪式完成。

### 2.2 中段：身份恐惧

玩家以为自己是来找人的新郎，后期会发现：自己的记忆、婚书和家族委托都可能是仪式预先留下的证据。

### 2.3 终局：道德恐惧

玩家不能证明营救完全出于爱。寻找、命名、承诺和占有之间只有一线之隔。最终选择不是正确答案，而是玩家愿意承担哪一种后果。

### 2.4 贯穿全程：措辞侵蚀与剥夺阶梯

恐怖落在"谁在说话"上。仪式逐步接管替玩家叙述的字，但**换字不夺权**：侵蚀只改写显示文案，绝不改动 `choice.id`、`condition`、`next` 与结局门控——玩家做的始终是他原本要做的选择，变的只是这句话由谁开口。

| 渗透 | 被接管的内容 |
|---|---|
| 2 | 选项措辞改口（叙述性的"你"→"新郎"）；正文里的"她"换成玩家此刻最常用的称呼 |
| 3 | 顶栏时辰加礼数缀；遗物栏空态改词 |
| 4 | 顶栏按钮改称（存档→存名）；主菜单与结局录这层"现实锚点"失守 |
| 5 | 正文叙述连"你"都不再给玩家 |

唯一的例外是**节点剥夺**：在极少数仪式节点上，游戏真的替玩家落笔。门槛极高——必须由两条可识别预警铺满、且渗透达标（见 §3 第 7 条）。第一章只有两处：定名时的"喜婆替你落笔"、照面时的"沉默看她念完"。每次剥夺都在回看账上留下不可抵赖的一行。

## 3. 体验原则

1. 不显示理智、阴气、恐惧值等生存条。
2. 不采用随机跳吓、强制乱码或随机即死。
3. 每次异常都能被回溯验证。
4. 玩家失败不是点错一个按钮，而是长期接受规则给出的安全解释。
5. 新娘的恢复表现为停顿、拒绝和提出无关问题，而不是好感度增加。
6. 文本恐怖优先：重复措辞、否认、沉默、错误称呼和场景差量比数值变化更重要。
7. 任何死亡都必须由明确抉择导致，且此前至少出现两条可识别预警。
8. **证据面永远诚实。** 回看账页、遗物原文、未失守的现实锚点不许被仪式改写——被改写的证据就不算证据，第 3 条会当场破功。
9. **玩家亲口说出的话不许被接管。** 中文的"你"两种用法同形（叙述里的"你"与角色对话里的"你"），引号判断不够，故在剧本上显式标注 `spoken` / `noErode`。否则渗透越深，玩家越说不出《失讳》那句"我把你的失踪当成了我自己的损失"——就成了惩罚好奇心，与主题相反。
10. **写状态不得发生在渲染期。** 文案推导必须是纯读；重访差量不许空口宣称异常，必须真比对基线（账页行数基线由"合上婚书"这个玩家动作落盘）。

## 4. 隐藏状态

玩家不可直接看到数值，但引擎可保存最小状态：

```js
{
  version: 3,
  scene: "arrival",
  flags: {},
  evidence: {
    paternal: 0,
    marital: 0,
    personal: 0
  },
  rite: 0,
  hour: 0,
  visited: {},
  transcript: []
}
```

### 4.1 `evidence`

记录玩家已经获得哪一类命名证据：

- `paternal`：父亲与原生家族留下的证据。
- `marital`：夫家、婚书、牌位与仪式身份证据。
- `personal`：新娘自己主动写下的名字、记号和愿望。

这些值不显示为进度条。它们只改变场景措辞、人物称呼和终局可用选项。

### 4.2 `rite`

仪式渗透度，范围建议为 `0—5`。它不是理智，不控制即死。

| 档位 | 已实现的表现 |
|---|---|
| 0 | 异常只来自环境和他人 |
| 1 | 重复物件轻微位移 |
| 2 | 选项措辞与正文称呼开始被接管 |
| 3 | 顶栏时辰加礼数缀、遗物栏空态改词 |
| 4 | 顶栏按钮改称；主菜单与结局录这层锚点失守 |
| 5 | 叙述连"你"都不再给玩家 |

`rite` 主要通过选择、称呼和是否主动完成礼数上升，不通过点击随机幻象上升。

**关键约束：** `rite` **不改变任何结局的达成条件**——结局只按"你用什么称呼了她"收束。但它门控定名之门的礼数要求（见 §8.6），从而保证每一局通关都必然穿过第一档措辞侵蚀。

### 4.3 `transcript`

保存最近 30 条事件，用于让同一场景二次进入时产生可验证的文本差异。

**它不能作为回看证据的真值源**——滚动窗口会把旧事件挤掉。凡"玩家做过什么"必须能核对的，一律落在持久 `flags`（违规用 `answeredName` / `liftedVeil`，被代笔用 `usurped-<场景>:<选项>` 前缀）；`transcript` 只作辅助。

## 5. 叙事框架

玩家是一个从未见过未婚妻的准新郎。家族只交给他一封残缺婚书和一个名字。新娘在婚期前失踪，唯一找到的地方是浙东老宅。

玩家进入后得知：

- 村民坚称婚礼尚未开始。
- 喜婆坚称新娘一直在轿中。
- 账本说她从未出生。
- 牌位说她已嫁入陈门。
- 纸鸢背面有一个不完整、不属于任何家族的名字。

新娘被仪式拆成多个“称呼”：某家女儿、某门新妇、某郎之妻、纸上的新娘。玩家恢复她的过程，就是判断哪一种称呼和她自己有关。

## 6. 三条名字与三种结局

### 6.1 父家之名：《归籍》

玩家选择承认她原生家庭给予的身份。

表层结果：婚礼终止，村口开启，新娘离开老宅。

真实结果：她只是从夫家所有权转回父家登记，仍未获得自主身份。

结局语气：安静、正确、没有暴力。最后一句是她平静道谢。

### 6.2 夫家之名：《正婚》

玩家选择按照婚书、牌位和村民认可的方式叫她。

表层结果：所有规则突然一致，仪式圆满完成，玩家安全离开并获得最高奖励。

真实结果：玩家成为仪式共犯。此后收到署名完整、寄件人却是自己的喜帖。

恐怖类型：奖励玩家服从，而不是惩罚玩家失误。

### 6.3 自拟之名：《失讳》

玩家选择她私人写下的名字，即使无法证明读音或完整写法。

表层结果：礼制崩坏、村路消失、玩家反复回到婚礼当晚。

真实结果：她恢复为能够提问的人。她首先问：

> “既然记得我，你为什么还要娶我？”

玩家必须承认自己的寻找也曾是一种占有。最终可选择放弃婚书、归还姓名，或者让她自己决定去留。

该结局不是机械胜利，也是主结局候选。

## 7. 核心循环

1. 进入场景，读取当前环境与他人的说法。
2. 检查物品、碑文、婚书和重复措辞。
3. 做出带代价的选择，不提前显示数值。
4. 离开后回到同一场景，观察文字与物件如何变化。
5. 发现旧信息被重新称呼或重新解释。
6. 更新对新娘身份的判断。
7. 终局选择用哪一种名字承认她。

探索不要求集齐道具。玩家即使没有拿到全部物品，也可以通过不同证据组合进入三种结局。

## 8. 章节结构

MVP 实现一章完整闭环，而不是先把全部旧剧情数值迁移。

### 8.1 入宅

玩家因新娘失踪进入老宅。第一条规则：“不要回应堂外叫名者。”

### 8.2 三处证据

- 西厢：账本、嫁妆单、父亲书信。
- 东厢：空轿、镜台、婚书和私人纸鸢。
- 祠堂：牌位、族谱、喜婆的仪式记录。

每处至少提供两种互相矛盾的解释。

### 8.3 第一次重逢

新娘短暂现身，但只会重复礼词。玩家的选择决定下一次她能否多说出一个词。

### 8.4 规则反噬

原本保护玩家的规则被重新解释：

- “不回应叫名者”实际上禁止她呼唤自己。
- “不揭盖头”使她永远停留在新娘身份。
- “不系红绳”并非保护，而是让她不能主动选择。

### 8.5 命名终局

三种名字依次呈现，没有明确推荐。玩家选择后经历对应后果，并进入三种结局之一。

### 8.6 回看账页与定名门（2026-09-14 增）

**回看账页 `margins`（婚书边角）** —— 中庭"低头看你自己的婚书"进入，随时可去、不设门控。它把每条违规、每次被代笔、仪式当前状态落成一行行可核对的字，是体验原则第 3 条的落地装置。它标 `noErode`：**证据面必须永远诚实**。重访时不许空口宣称"又多出一行"，必须与"合上婚书"时记下的行数真比对；没变多就明说没变。

**定名门** —— `evidenceTotal >= 1 且 rite >= 2`（先应下规矩、再去祠堂问牌位，各 +1）。

为什么加礼数要求：审计测得三条最短结局路线抵达时 `rite` 全为 0，意味着措辞侵蚀、节点剥夺、锚点失守这些核心内容，急着通关的玩家一次都看不到。门槛提高后每一局都必然穿过第一档侵蚀。

为什么不是惩罚好奇：门槛只要求"行礼"，而行礼本身是自愿的；纯守规矩不违一条也能开门。仪式靠服进而非冒犯推进——这本身就是主题。

**门必须可见。** 证据攥在手里而礼数未行时，中庭给一条 `disabled` 的说明项（「礼数一行未行，此处轮不到你开口」），而不是静默隐藏定名——§11 明令禁止"结局条件完全不透明"。

## 9. 内容规模

下一章目标（保留为标尺）：

- 1 个完整章节。
- 25—35 个节点。
- 3 条可完成路线。
- 3 个结局。
- 15—25 分钟单周目。
- 2—3 周目体验完整差异。
- 不实现战斗、谜题计时、开放地图和复杂背包。

### 9.1 当前垂直切片实测（2026-09-14）

| 项 | 实测 |
|---|---|
| 场景 / 选项 / 差量文案段 | 20 / 47 / 48 |
| 结局 / 遗物 | 3 / 5 |
| 正文（含全部变体） | 2890 字 |
| 加结局与遗物原文 | 3453 字 |
| 典型随机周目 | 64 次点击、渲染 3504 字 ≈ 12 分钟（打字机约 3 分 + 阅读约 9 分） |
| 三条最短结局路线 | 7 / 11 / 12 次点击（依次收束于代笔落笔、《归籍》、《失讳》），**抵达时 rite 均为 2** |
| 随机 3000 局分布 | 正婚 53.9% · 失讳 27.6% · 归籍 18.4% |

**量时长的一个坑：** 不要用最短路线的纯文本字数当周目时长。第一版审计据此得出"2.5–3.6 分钟、比目标差一个量级"，漏算了打字机耗时与重访场景的重复渲染，实际接近目标下沿。

**未达项：** 节点数 20 < 25—35。第一章是闭环切片，扩体量属下一章工作。

## 10. 技术目标架构

当前引擎可以保留渲染与存档骨架，但场景应从过程式 `run()` 字符串逐步迁移到数据合同：

```js
{
  id: "hall",
  title: "喜堂",
  text: {
    first: "……",
    again: "……",
    rites: ["……", "……"]
  },
  choices: [
    {
      id: "answer-name",
      label: "回应门外叫名",
      condition: { notFlag: "answeredName" },
      effects: { flag: "answeredName", rite: 1 }
    }
  ]
}
```

### 10.1 已落地的数据字段（2026-09-14）

原设想已实现并扩展。写新章节只需加数据，不必改引擎：

| 字段 | 含义 |
|---|---|
| `text.first` / `text.again` | 字符串，或按 `when` 取首个成立项的数组（必须以无 `when` 的兜底项收尾，否则渲染抛错） |
| `textFn` | 完全由状态推导文案的场景（回看账页）。其重访差量须由真实比对产生 |
| `noErode` | 该场景正文与选项一律不被措辞侵蚀（证据面、玩家自白处） |
| `spoken` | 该选项是玩家亲口对别人说的话，不许被仪式接管 |
| `usurp:{minRite, warn[]}` | 节点剥夺：`warn` 中已置位 >=2 且 `rite>=minRite` 时，点击额外记 `usurped-*` 并触发锚点失守 |
| `marksRows` | 玩家动作里落账页行数基线（写状态不在渲染期） |
| `disabled` | 可见但不可点的说明项，用于"门开着，且写明白为何不能进" |
| `condition` 谓词 | `flag` `notFlag` `item` `notItem` `memory` `rite` `riteUnder` `minEvidence` `evidenceTotal` |
| `effects` | `flag` / `flags[]` / `item` / `rite` / `evidence{}`；后两类按"场景:选项"记账，重复点击不叠加 |

落地时放弃了兼容层，采用彻底替换（原方案曾打算保留过渡层）：

- 新增 `chapter-v3.js` 场景解释器，`js/scenes.js`、`js/scenes_ayuan.js`、`js/scenes_po.js`、`js/systems.js`、`data/events.js` 全部删除。
- 保留 `G.flags`、`G.visited`、`saveGame/loadGame` 这三件仍然成立的基础。
- 新增 `evidence`、`rite`、`transcript`，读档时做完整类型归一。
- 理智/阴气 UI 与旧存档字段一并移除，不做"读取后忽略"——存档键改为 `hongzhiyuan_save_v3`，v2 进度自然失效。
- 新游戏从 `version: 3` 开始。

放弃兼容层的原因：兼容层会让旧结局表、成就系统与随机事件这三套 v2 模型继续存活，而它们各自都假设了"玩家有生存数值"这一已被否定的前提。留着它们，状态契约和测试都会持续被污染。

## 11. 文本异变合同

异变只能来自确定性状态：

- 证据值达到阈值。
- `rite` 达到档位。
- 某选项已经选择。
- 某场景已进入第二次。
- 某 NPC 已被玩家纠正称呼。
- 玩家已违规（`answeredName` / `liftedVeil` / `burnedMarriagePaper`）。
- 玩家已被代笔（`usurped-<场景>:<选项>`）。
- 是否已被这个故事记住（`memory`，用于二周目碑文变体）。
- 账页行数与上次合上时的基线之差。

禁止：

- 无原因随机插入乱码。
- 随机扣隐藏生命。
- 同一输入随机得到不同剧情结果。
- 结局条件完全不透明。
- 仅靠恐怖图片、音效或文字闪烁推动剧情。
- **在渲染期写状态。** 文案推导必须是纯读；否则同一状态两次渲染不一致，破坏确定性。需要落基线的，放进玩家动作。
- **无条件宣称异常。** 重访时不许直接说"又多出一行"，必须真比对；没变就说没变。作者空口编造异常，等于废除第 3 条。

## 12. 美术与声音

- 背景保持宣纸、烛光和朱砂三层结构，但移除数值血条。
- 异常优先使用排版变化：称呼替换、空白扩大、重复句、破折号未完成。
- `rite` 高时只改变一个词的重复，不做满屏故障。
- 音效从“恐怖惊吓”转为动作反馈：纸声、木鱼、雨滴、唢呐残响。
- 新娘主题音从礼乐逐渐失去一个声部，表现主体缺失。

### 12.1 UI 分层侵蚀的边界

界面文字也是"字"，因此也在争夺范围内——但必须分层，否则锚点从未立住，异常就退化成背景噪音：

- **游戏内 UI**（选项措辞、顶栏时辰、遗物栏）随渗透中期起被侵蚀。
- **现实锚点**（主菜单、结局录）默认诚实，只在 `rite>=4` 或已被代笔（`anchorFall`）时失守。锚点失守本身是终局级的一击，不能提前花掉。
- 失守由实时 `G` 驱动，不做持久污染：新开一局 `freshState()` 即恢复诚实。

两条铁律：

1. **只改 label，绝不动 `onclick`/handler。** 把玩家唯一的出路锁死是软锁，不是恐怖。
2. **文案一律从诚实常量重算，不做增量改写。** 读 DOM 原值再改一次会被上一档污染，且新开一局复原不了。

### 12.2 无障碍

- 自定义 `:focus-visible` 朱砂焦点环，不依赖浏览器 UA 默认。
- 顶栏按钮与遗物项触摸目标 44px；允许缩放（不设 `user-scalable=no`）。
- `prefers-reduced-motion` 关掉打字光标闪烁、纸鸢飘落、震动与闪白——但**保留仪式渗透的色调与暗角变化**：它是本作唯一的进度可见性，不是装饰。
- 打字机每约 30ms 改写 `innerHTML`，配 `aria-live` 会逐字重播整段；用 `aria-busy` 抑制，打完或跳过时才播报一次。
- 锁门说明项带 `aria-disabled` 且无点击处理。
